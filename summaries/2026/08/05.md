1.  **Notification Burst Logic:**
    *   **Mechanism:** Describes a system using a deque (double-ended queue) to detect "notification bursts." A burst occurs when `C` notifications are received within a `T` time threshold.
    *   **State Variable:** A boolean `isSpecialNotificationShown` tracks if a special notification has already been displayed for a burst.
    *   **Process Flow:**
        *   Notifications (`T0`, `T1`, `T2`, etc.) are pushed to the front of the deque.
        *   If deque length is less than `C`, it's not a burst; a normal notification is shown.
        *   If deque length is `>= C`, the latest notification's timestamp (`T_new`) is compared with the oldest one in the deque (`T_old`).
        *   If `T_new - T_old < T`, it's a burst. A special notification is shown *only once* per burst (`isSpecialNotificationShown` ensures this), or the notification is discarded. The deque is updated by popping the back and pushing the front.
        *   If `T_new - T_old >= T`, it's not a burst (threshold exceeded). A normal notification is shown, the deque is cleared, and `T_new` is pushed as the only element, resetting `isSpecialNotificationShown`.
    *   **Parameters & Examples:** `T = 15` (time threshold) and `C = 3` (count threshold) are used in examples to illustrate burst detection. The examples provided simulate various notification arrival times and how the deque and burst logic would behave.
